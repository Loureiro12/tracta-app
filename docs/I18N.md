# Internacionalização (i18n)

Stack: `i18next` + `react-i18next` + `expo-localization`. Idiomas: `en` (fonte e fallback) e `pt-BR`.

## Onde cada coisa mora

| Caminho                                               | Papel                                                                 |
| ----------------------------------------------------- | --------------------------------------------------------------------- |
| `apps/mobile/src/shared/i18n/`                        | mecânica: `initI18n`, `changeLocale`, resolução de locale, formatação |
| `apps/mobile/src/features/<f>/i18n/{en,pt-BR}.json`   | copy da feature (namespace `<f>`), exportada pelo barrel              |
| `apps/mobile/src/app-providers/i18n/common/`          | namespace `common` (nome do app, ações genéricas, erros)              |
| `apps/mobile/src/app-providers/i18n/resources.ts`     | composição de todos os namespaces (uma linha por feature)             |
| `apps/mobile/src/app-providers/i18n/i18next.d.ts`     | tipagem das chaves a partir de `en.json`                              |
| `apps/mobile/src/app-providers/i18n/I18nProvider.tsx` | sincroniza i18next com a preferência persistida e com deep links      |

## Usando nas telas

```tsx
import { useTranslation } from '@/shared/i18n';

const { t } = useTranslation('home');          // namespace da feature
<Text>{t('counter.taps', { count })}</Text>    // plural: taps_one / taps_other
<Button label={t('nav.settings')} ... />

const { t } = useTranslation(['home', 'common']);
t('common:appName');                            // outro namespace com prefixo
```

- Chaves são tipadas: `t('nav.typo')` falha no typecheck.
- Plurais usam o sufixo CLDR (`_one`, `_other`). Em pt-BR, `0` e `1` caem em `_one`.
- Interpolação: `{{value}}`. Nunca concatene strings traduzidas.
- Datas e números: `formatDate`, `formatNumber`, `formatCurrency` de `@/shared/i18n`.

## Regras aplicadas automaticamente

- ESLint `i18next/no-literal-string` em `src/features/**` e `app/**`: texto JSX e as props `label`, `placeholder`, `helperText`, `errorText`, `title`, `accessibilityLabel` precisam vir de `t()`.
- ESLint proíbe importar `react-i18next`/`i18next` fora de `shared/i18n` e `app-providers/i18n`.
- `check-structure`: toda feature tem `i18n/en.json`, `i18n/pt-BR.json` e `i18n/index.ts`; `pt-BR.json` tem exatamente as mesmas chaves de `en.json` (faltando ou sobrando é erro); o namespace está registrado em `resources.ts`.
- `pnpm gen:feature` já cria tudo isso ligado.

## Preferência do usuário

`settings.localePreference` (`system` | `en` | `pt-BR`) fica no store persistido em AsyncStorage. `system` resolve pelo primeiro idioma do aparelho (`pt-PT` cai em `pt-BR`, `en-GB` em `en`). Mudar a preferência re-renderiza o app inteiro sem reiniciar.

iOS lista os idiomas em Ajustes > Tracta graças a `supportedLocales` no plugin do `expo-localization`; Android gera `locales_config.xml`.

## E2E

Os fluxos não dependem do idioma do simulador: todo deep link aceita `?locale=en|pt-BR`, e o subflow `launch.yaml` já abre `tracta://?locale=en`. O fluxo `settings/settings-language.yaml` cobre a troca para pt-BR, plurais e o override por deep link.

## Adicionando um idioma

1. Acrescente o tag em `SUPPORTED_LOCALES` (`shared/i18n/locales.ts`) e em `LOCALES` do `check-structure`.
2. Crie `<tag>.json` em cada namespace (o check aponta todos os que faltam).
3. Registre em `resources.ts` e no `supportedLocales` do `app.config.ts`.
4. Adicione a opção em Settings e um testID `settings.language.<tag-kebab>`.
